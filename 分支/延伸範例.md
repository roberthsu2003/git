# 延伸練習：分岔與合併衝突

完成[分支與合併](./README.md)後，可在獨立的練習專案操作本頁。兩個案例按順序執行；使用 macOS／Linux 終端機或 Windows Git Bash，已設定提交身分，且練習位置沒有 `merge-demo`。

## 案例一：兩邊改不同檔案

```bash
mkdir merge-demo
cd merge-demo
git init -b main
printf 'Home\n' > index.txt
git add index.txt
git commit -m "建立首頁"
git switch -c feature-about
printf 'About\n' > about.txt
git add about.txt
git commit -m "新增團隊介紹"
git switch main
printf 'Contact\n' > contact.txt
git add contact.txt
git commit -m "新增聯絡資訊"
git merge --no-edit feature-about
git log --oneline --graph --all
```

main 和 feature-about 各自增加提交，因此這次建立合併提交；main 最後同時有 `about.txt` 和 `contact.txt`。`--no-edit` 使用預設合併訊息。

## 案例二：兩邊修改同一行

接續 `merge-demo`，先讓兩個分支把首頁改成不同內容：

```bash
git switch -c feature-title
printf 'Welcome\n' > index.txt
git add index.txt
git commit -m "更新功能分支標題"
git switch main
printf 'Hello\n' > index.txt
git add index.txt
git commit -m "更新主要分支標題"
```

在 main 執行 `git merge feature-title`，Git 會因同一行有不同修改而暫停。用 `git status` 確認衝突檔案，在編輯器開啟 `index.txt`，決定最後內容並移除 `<<<<<<<`、`=======`、`>>>>>>>` 標記。本練習將內容改成 `Hello and welcome`，再完成合併：

```bash
printf 'Hello and welcome\n' > index.txt
git add index.txt
git commit -m "整合首頁標題"
cat index.txt
git status --short
```

預期顯示 `Hello and welcome`，工作區乾淨。真實專案應與相關人員確認要保留的內容，不能只刪標記。若決定取消尚在進行中的 merge，可以使用 `git merge --abort`。
