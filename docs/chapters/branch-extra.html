延伸練習：分岔與合併衝突

完成分支與合併後，可在獨立的練習專案操作本頁。兩個案例按順序執行；使用 macOS／Linux 終端機或 Windows Git Bash，已設定提交身分，且練習位置沒有 merge-demo。

案例一：兩邊改不同檔案

bash
mkdir merge-demo
cd merge-demo
git init -b main
printf 'Home\n' > index.txt
git add index.txt
git commit -m "建立首頁"
git switch -c feature-about
printf 'About\n' > about.txt
git add about.txt
git commit -m "新增團隊介紹"
git switch main
printf 'Contact\n' > contact.txt
git add contact.txt
git commit -m "新增聯絡資訊"
git merge --no-edit feature-about
git log --oneline --graph --all

main 和 feature-about 各自增加提交，因此這次建立合併提交；main 最後同時有 about.txt 和 contact.txt。--no-edit 使用預設合併訊息。

案例二：兩邊修改同一行

接續 merge-demo，先讓兩個分支把首頁改成不同內容：

bash
git switch -c feature-title
printf 'Welcome\n' > index.txt
git add index.txt
git commit -m "更新功能分支標題"
git switch main
printf 'Hello\n' > index.txt
git add index.txt
git commit -m "更新主要分支標題"

停點一：製造衝突

操作位置：merge-demo 的 main，工作區乾淨。以下 merge 預期會失敗並停在衝突狀態，這就是本次要觀察的結果。

bash
git merge feature-title
git status --short
cat index.txt

停點二：辨認並手動處理

停下核對： status 顯示 UU index.txt；檔案內有 <<<<<<<、=======、>>>>>>>。先指出哪一側是 main 的 Hello、哪一側是 feature-title 的 Welcome。

在編輯器開啟 index.txt，親手把內容改為一行 Hello and welcome，移除衝突標記並儲存。老師先等全班完成，不要直接貼覆寫檔案的指令。下面文字是要在編輯器保留的內容，不是終端機指令：

text
Hello and welcome

停點三：記錄解決結果

先查看差異，確認保留內容正確，再完成合併：

bash
git diff
git add index.txt
git commit -m "整合首頁標題"
cat index.txt
git status --short

預期顯示 Hello and welcome，工作區乾淨。真實專案應與相關人員確認要保留的內容，不能只刪標記。若決定取消尚在進行中的 merge，可以使用 git merge --abort。
