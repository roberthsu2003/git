教師課程安排

課程主線為 VS Code 入門與日常練習 → 深入建立版本 → 分享與協作 → 復原及延伸。先讓學生用 Source Control 累積 Commit 經驗，再以 VS Code Terminal 理解指令，之後才增加遠端、多人合作與歷史操作。互動圖解用於解釋狀態，不必依圖解編號當作上課順序。

建議教學安排

以下為可調整的單元，不限定每單元一堂課。入門安排在第一個程式範例完成後；後續 Commit 練習穿插在原有課程，無須等 Git 專門章節才開始。

單元章節與重點課堂任務驗收方式
準備安裝 Git、VS Code，設定提交身分及 Terminal開啟練習資料夾，確認 Git 版本能說出目前操作的資料夾
入門VS Code Source Control：Repository、Changes、Stage、Commit完成第一個範例並建立 Commit能解釋 Commit 的用途並跟著操作
日常練習每個範例後查看差異、Stage、Commit前 1～2 次完整示範，第 3～4 次口頭提示，之後由學生獨立操作能選對檔案並寫出描述修改的訊息
深入版本熟悉幾次 Commit 後，學 01 工作區與暫存區、02 分支與歷史在 Terminal 操作，對照 Source Control；再練習 Stage 後修改能說明 Commit 保存哪一版；HEAD 細節可稍後深入
分支03 分支與合併、04 .gitignore建立分支新增功能，提交並合併；排除不需追蹤的檔案能獨立完成基本流程；需要時提早教 .gitignore
分享與合作GitHub 基本操作、Remote、Push、Pull，接著 05 PR推送練習專案，兩人分工並互相檢查 PR能說明本機與遠端、Push、Pull、PR 的差別
依需求06 Fork、09 取消暫存與未提交修改的處理依交作業情境使用 Fork；在練習專案處理修改能說出操作目的與可能影響
進階選讀07 worktree、08 AI 節奏、10 reset、11 amend，以及 tag、rebase依需求在獨立練習專案實作先預測影響，操作後檢查並解釋結果

日常每個範例預留約 2～5 分鐘：執行範例、查看 Changes、Stage、輸入訊息、Commit。第一次完整入門可預留約 20～30 分鐘。若學生尚未熟悉 Terminal，先練習路徑、建檔及讀檔；需要忽略虛擬環境等檔案時，不必等到分支單元才教 .gitignore。

每一個概念的帶課方式

  1. 先看情境： 說明目前要解決的問題，例如功能未完成但臨時要修 bug。
  2. 停在圖解操作前： 讓學生預測哪個檔案、分支或區域會改變。
  3. 逐步看圖： 按下一步，請學生用自己的話解釋差異。
  4. 實際操作： 入門先用 Source Control；深入章節在 VS Code Terminal 輸入指令並對照圖形介面，每次確認位置、分支與結果。
  5. 自己完成任務： 不提供全部指令，讓學生依完成標準選擇操作。

圖解用來理解狀態，Source Control 與終端機用來操作和驗證。學生需要練習自己閱讀差異與輸出，不能只複製指令或 AI 的完成報告。

評量建議

請學生交「成果檔案、相關 commit／PR、實際檢查結果、自己對差異的解釋」。以能否完整完成任務與解釋操作為主，不只考指令名稱。

簡易評量：

  • 能確認資料夾、分支與修改狀態。
  • 每筆提交有清楚用途，沒有混入無關檔案。
  • 合作時選對 PR 來源與目標，能更新本地 main。
  • 會選擇適當的復原方法，能說出哪些內容將被改變。

其他 AI、文案與跨領域備課素材已整理到 延伸主題，不列入 Git 主線。
