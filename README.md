# Git 學習筆記

從第一筆 commit，到跟同學一起完成專案。這份教材以「先看圖解 → 跟著操作 → 自己完成任務」安排學習順序。

**[▶ 開啟互動圖解教室](https://roberthsu2003.github.io/git/)** · [教師課程安排](./課程/README.md) · [練習與測驗](./測驗/README.md)

## 第一次學習，從這裡開始

1. [準備 Git 與 VS Code](./環境安裝與設定/README.md)，設定提交身分。
2. [跟著 VS Code Source Control 入門](./VSCode入門/README.md)，完成第一筆 Commit。
3. 每次完成課程範例後，查看 Changes、Stage、Commit；熟悉後再進入下方的第 01 章。

## 自學方式

第一次學習，先完成環境準備與 [VS Code Source Control 入門](./VSCode入門/README.md)，在課程範例中練習幾次 Commit，再讀第 01～04 章。接著依需要學習 GitHub 基本操作與第 05 章；向別人的專案交作業時讀第 06 章。第 07～08 章及進階歷史操作可依需求選讀。每章先看概念、親手執行範例，再完成「自己做」確認理解。

日常範例以 VS Code **Source Control** 查看、Stage 與 Commit；專門章節透過 VS Code **Terminal** 深入理解 Git 指令。兩種介面操作的是同一個 Repository。遇到不應提交的檔案時，可提早查閱第 04 章。

各章的範例通常會建立各自的練習資料夾，請以章內寫的起點和操作位置為準；同一章的連續步驟則要按順序執行。看到輸出的 commit 識別碼和路徑與教材不同是正常的。若資料夾名稱已存在，請選擇新的練習位置，不要覆蓋原有資料。

單人自學時，第 05 章可以先閱讀網頁操作並了解 PR 流程；兩人實作需要夥伴與儲存庫權限，不必為了繼續學習而等待。

## 開始之前

先完成 [環境安裝與設定](./環境安裝與設定/README.md)：準備 Git、VS Code 與其 Terminal，設定提交用的姓名與電子郵件。Windows 的指令練習請在 VS Code Terminal 使用 Git Bash。

操作前先確認三件事：**在哪個資料夾？在哪個分支？這一步會改變什麼？** 用 `pwd`、`git branch --show-current`、`git status` 檢查。

## 課堂跟做與卡關

每個案例以「老師示範一段 → 學生操作 → 核對結果 → 解釋變化」進行。不要一次貼完整章的指令。各章的開始條件與完成狀態，請對照[教師課程安排的核對表](./課程/README.md#課堂案例核對表)；章末「換你做」會增加提交或檔案，完成狀態以進入自主練習前為準。

結果不同時，先停在目前狀態，保留錯誤訊息。用 pwd、git branch --show-current、git status 核對位置與狀態，將「最後成功的一步、剛執行的指令、完整錯誤」告訴老師。不要重貼整段、刪除 .git 或自行 reset。若進度差太多，先保留原資料夾，由老師協助在新的同層資料夾從案例起點重做，後續路徑也要一起替換。

若 log、show 或 diff 進入常見的 less 閱讀畫面，看到 `(END)` 時可按 q 回到提示符號，再輸入下一個指令；這不是 Git 卡住，也不是提交訊息編輯器。

## 第一階段｜建立版本

目標：自己建立記錄點，能試做新功能，也能保留原本可用的版本。

| 章節 | 學習內容 | 完成後你能做什麼？ |
| --- | --- | --- |
| 01 | [工作區與暫存區](./開始使用Git/README.md) | 用 add 與 commit 保存正確的檔案版本 |
| 02 | [main、HEAD 與歷史](./使用main主要分支/README.md) | 看懂目前分支與各筆 commit 的關係；HEAD 細節可在熟悉提交後再讀 |
| 03 | [分支與合併](./分支/README.md) | 在功能分支開發，完成後整合回 main |
| 04 | [忽略不需要追蹤的檔案](./不想被追蹤的檔案/README.md) | 用 .gitignore 排除暫存檔，理解已追蹤檔案的差別 |

**階段任務：** 建立一個小專案，在獨立分支新增關於我們頁面，提交並合併回 main。能說出工作區、暫存區與 commit 的差別，就可以繼續。

選讀：[圖解比較合併方式](./分支/合併方式比較.md)，用同一個小專案比較歷史與 GitHub PR 選項。

## 第二階段｜一起開發

目標：先理解 Remote、Push 與 Pull，再學會分享成果並檢查後整合。第 05 章是協作主線；第 06 章依交作業需求閱讀，第 07～08 章是延伸。

先閱讀 [GitHub 基本操作](./github/README.md)第 1～2 節，了解帳號、登入與 clone，再認識第 4～5 節的 Remote、Push、Pull；可依情境選第 3 節將自己的本地專案推上 GitHub。需要設定時，查閱 [SSH](./ssh/README.md) 或 [憑證](./credential/README.md)。

| 章節 | 學習內容 | 完成後你能做什麼？ |
| --- | --- | --- |
| 05 | [GitHub 共同開發](./協作與PullRequest/README.md) | 兩人各開分支，用 PR 檢查並合併成果 |
| 06 | [用 Fork 交作業](./Fork交作業/README.md) | 沒有老師專案的寫入權限，也能提出修改 |
| 07 | [worktree：多任務工作](./worktree/README.md) | 保留未完成的功能，在另一個資料夾修 bug |
| 08 | [AI 開發的 Git 節奏](./日常工作流程/README.md) | 小步修改、閱讀差異、驗證後提交，再用 PR 整合 |

**階段任務：** 兩人完成班級介紹，各自送 PR、互相檢查、合併後更新本地 main。單人自學可先描述各步驟的目的，有夥伴時再實作。選讀第 08 章後，可另外模擬一次 AI 修改失敗並練習處理。

## 第三階段｜復原與整理

目標：分清楚修改還沒提交、已暫存與已提交的情況，再選對復原方法。第一輪可先學第 09 章的取消暫存與未提交修改處理；第 10～11 章屬進階，在理解提交歷史後按需練習。

| 章節 | 學習內容 | 完成後你能做什麼？ |
| --- | --- | --- |
| 09 | [還原檔案與取消暫存](./回復被刪除的檔案或被編輯的內容/README.md) | 分辨 restore、取消暫存與已提交版本的復原 |
| 10 | [reset 的三種模式](./git_reset/README.md) | 比較 soft、mixed、hard 改變哪些區域 |
| 11 | [整理最後一筆提交](./修改目前commit/README.md) | 在尚未分享的提交上練習 amend |

**階段任務：** 在獨立練習專案中製造三種修改狀態，先預測結果，再操作驗證。不要把共享 main 當作修改歷史的練習場。
