# 教師課程安排

課程順序與 [教材首頁](../README.md)、[互動圖解教室](../docs/README.md) 一致：**建立版本 → 一起開發 → 復原與整理**。先讓學生完成一次正常流程，再增加多人合作與歷史操作。

## 建議的五次課堂

以下為可調整的安排，不限定每堂時數。若學生還不熟終端機，先用一堂準備課練習路徑、建檔、讀檔與編輯器操作。

| 課堂 | 章節與重點 | 課堂任務 | 驗收方式 |
| --- | --- | --- | --- |
| 準備課 | 環境安裝、終端機與編輯器 | 建立資料夾與 index.txt，設定提交身分 | 學生能說出目前操作位置 |
| 第 1 次 | 01 工作區與暫存區、02 main 與 HEAD | add 後再次修改，預測 commit 會保存哪版 | 對照檔案、status 與 log 解釋結果 |
| 第 2 次 | 03 分支與合併、04 .gitignore | 新增關於我們頁面，再合併回 main | 可獨立完成建立、切換、提交、合併 |
| 第 3 次 | GitHub 前置設定、05 共同開發、06 Fork | 兩人分工，互相檢查 PR；以 Fork 提出作業 | 說明 push、PR、merge、pull 的差別 |
| 第 4 次 | 07 worktree、08 AI 開發的 Git 節奏 | 保留未完成修改，另一邊修 bug；檢查 AI 修改 | 正確選擇工作資料夾，附實際驗證結果 |
| 第 5 次 | 09 restore、10 reset、11 amend | 在練習專案比較三種修改狀態與復原方式 | 先預測影響區域，操作後解釋結果 |

時間不足時，先完成第 1～3 次的正常合作流程，第 4～5 次作為後續課程。rebase 與 tag 留作延伸，不混進第一輪基礎練習。

## 每一個概念的帶課方式

1. **先看情境：** 說明目前要解決的問題，例如功能未完成但臨時要修 bug。
2. **停在圖解操作前：** 讓學生預測哪個檔案、分支或區域會改變。
3. **逐步看圖：** 按下一步，請學生用自己的話解釋差異。
4. **實際操作：** 回章節講義輸入指令，每次確認位置、分支與結果。
5. **自己完成任務：** 不提供全部指令，讓學生依完成標準選擇操作。

圖解用來理解狀態，終端機用來驗證。學生需要練習自己閱讀差異與輸出，不能只複製指令或 AI 的完成報告。

## 評量建議

請學生交「成果檔案、相關 commit／PR、實際檢查結果、自己對差異的解釋」。以能否完整完成任務與解釋操作為主，不只考指令名稱。

簡易評量：

- 能確認資料夾、分支與修改狀態。
- 每筆提交有清楚用途，沒有混入無關檔案。
- 合作時選對 PR 來源與目標，能更新本地 main。
- 會選擇適當的復原方法，能說出哪些內容將被改變。

其他 AI、文案與跨領域備課素材已整理到 [延伸主題](./延伸主題.md)，不列入 Git 主線。
